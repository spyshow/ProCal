## Architecture & Data Flow Diagram

```
+-----------------------------------------------------------------------------------+
| EXTERNAL MULTIMODAL AI AGENT (Claude Desktop / Cursor / Custom Agent)             |
| 1. Reads Project Drawing (PDF / Floor Plan / Schedule) via native Vision          |
+-----------------------------------------+-----------------------------------------+
                                          |
          +-------------------------------+-------------------------------+
          | Option 1: Remote Streamable HTTP                              | Option 2: Local Stdio Bridge
          | POST /api/mcp (Authorization: Bearer procal_sk_...)           | npx tsx scripts/procal-mcp-stdio.ts
          v                                                               v (forwards JSON-RPC over HTTP)
+-----------------------------------------------------------------------------------+
| src/proxy.ts                                                                      |
| - All /api/* routes return 401 JSON when unauthenticated (never 307 /login HTML)  |
| - Requests with Authorization: Bearer procal_sk_... pass through to route handler |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| src/lib/auth.ts :: getSessionUser()                                               |
| 1. Checks session_token cookie (verified JWT, user.disabled === false)            |
| 2. Fallback: hashes Bearer procal_sk_... with SHA-256 -> looks up active ApiKey   |
|    (revokedAt === null && user.disabled === false), fire-and-forget lastUsedAt    |
+-----------------------------------------+-----------------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
| src/lib/mcp/server.ts (Zero-Dependency JSON-RPC 2.0 MCP Handler)                  |
|                                                                                   |
|  1. get_engineering_catalog   --> Country defaults, room VA/m2, AC rules, library |
|  2. validate_project_spec     --> Pre-flight check; flags missing electrical kW/V |
|                                   with IEC/NEMA defaults for Engineer confirmation|
|  3. create_project_from_spec  --> Interactive Prisma $transaction (15s timeout):  |
|                                   - 60s idempotency dedupe                        |
|                                   - Credit check & decrement (non-ADMIN)          |
|                                   - Pre-generated UUIDs + createMany() batching   |
|                                   - VA/kVA * PF -> Watts + back-calc loadDensity  |
|                                   - Complex-wide diversity + cableSize + ENGINE_V |
|  4. update_project_loads      --> Mutates loads/templates + global recalculate    |
|  5. check_project_compliance  --> Fast instant audit (VD, Ib<=Ir<=In<=Iz, unbal%) |
|  6. get_project_bom           --> Aggregated switchgear & cable takeoff schedule  |
|  7. get_project_sld           --> generateSLD() (incl. BuildingLoads) + schematex |
|                                   render() -> standalone SVG + AST JSON           |
|  8. get_project_report        --> Compliance summary + 1h signed ?token= PDF URL  |
|                                   + targeted /calculator?projectId=&floor= links  |
+-----------------------------------------------------------------------------------+
```

## Implementation Steps & Verification Proofs

### Step 1: Prisma `ApiKey` Model, Bearer Auth in `src/lib/auth.ts`, and `src/proxy.ts` Guard Fix
- **Files:**
  - `prisma/schema.prisma`: Add `ApiKey` model (`id`, `userId`, `name`, `keyPrefix`, `keyHash` `@unique`, `lastUsedAt`, `revokedAt`, `createdAt`) with relation to `User`. Run `npx prisma generate` and `npx prisma db push`.
  - `src/lib/auth.ts`:
    - Add `generateApiKey()` (`procal_sk_<48_hex_chars>`), `hashApiKey(rawKey)` (SHA-256), `signReportDownloadToken(projectId, userId)` (1h JWT with `purpose: "report-pdf"`), and `verifyReportDownloadToken(token, projectId)`.
    - Extend `getSessionUser()` to check `user.disabled === false` and, when no `session_token` cookie is present, inspect `headers().get("authorization")` for `Bearer procal_sk_...`, lookup `db.apiKey.findUnique({ where: { keyHash }, include: { user: true } })`, verify `!apiKey.revokedAt && !apiKey.user.disabled`, fire-and-forget `lastUsedAt` update (throttled >60s), and return the user.
  - `src/proxy.ts`: Exclude `/api/*` from HTML `/login` redirects (or return `401 { error: "Unauthorized" }` JSON when `/api/*` is hit without valid credentials and pass through `Authorization: Bearer procal_sk_...`).
- **How we prove it works:**
  - Unit & regression tests in `src/lib/__tests__/auth-api-key.test.ts` and `src/__tests__/proxy.test.ts` verifying cookie auth, valid/revoked/disabled `procal_sk_` Bearer keys, 1h signed report tokens, and 401 JSON (never 307 HTML) on `/api/*`.

### Step 2: Personal API Keys CRUD Route (`/api/api-keys`) & Settings/Dashboard UI
- **Files:**
  - `src/app/api/api-keys/route.ts`: `GET` (list active/revoked keys for current user returning only `id`, `name`, `keyPrefix`, `createdAt`, `lastUsedAt`), `POST` (create new `procal_sk_...` key, returning the raw key **once**), `DELETE` (revoke key by `id` owned by current user).
  - `src/components/ApiKeysModal.tsx` + integration in `src/components/AppHeader.tsx`: Modal allowing engineers to generate/revoke API keys and copy a ready-to-paste `claude_desktop_config.json` / `.cursor/mcp.json` snippet with their new API key pre-filled in one click.
- **How we prove it works:**
  - Unit tests in `src/app/api/api-keys/__tests__/route.test.ts` testing key creation, prefix-only listing, ownership enforcement on revoke, and UI component test with config snippet copy.

### Step 3: Shared Recalculation Service & SLD `BuildingLoad` Feeders Enhancement
- **Files:**
  - `src/lib/calculations/recalculate-project.ts`: Extract `recalculateBuilding(buildingId, options?)` and `recalculateProjectBuildings(projectId, options?)` from `src/app/api/buildings/[id]/recalculate/route.ts` so both the HTTP route and MCP tools share the exact same complex-wide residential coincidence factor and sizing logic.
  - `src/app/api/buildings/[id]/recalculate/route.ts`: Refactor to call `recalculateBuilding()`.
  - `src/lib/sld/generator.ts`: Update `generateSLD()` and `generateSLDPages()` so `bldg.buildingLoads` (elevators, fire pumps, booster pumps, HVAC) are emitted as dedicated MDB feeders (`mdb_bus -> bldg_load_bkr -> bldg_load`) with proper breaker ratings and cable sizes, and buildings with only `BuildingLoad` items still generate an SLD page.
  - `src/app/api/projects/[id]/pdf/route.ts`: Allow authentication via `?token=` (`verifyReportDownloadToken`) in addition to `verifyProjectAccess(id)` so 1-hour signed report links returned by MCP open directly.
- **How we prove it works:**
  - Existing `src/lib/sld/generator.test.ts` + new tests verifying `BuildingLoad` feeders appear in `generateSLD()` and `generateSLDPages()`, plus `recalculate` and `pdf/route.ts` signed token tests.

### Step 4: Declarative Project Drawing Spec, Pre-Flight Validator, and Atomic Builder
- **Files:**
  - `src/lib/agent/project-spec-schema.ts`: Zod schema (`ProjectDrawingSpecSchema` & `UpdateProjectLoadsSpecSchema`) supporting both architectural room inputs (`areaM2`, `hasAc`, `acBtu`, `loadDensityVaPerM2`) and electrical room overrides (`explicitLoadKw`, `explicitLoadKva`), building floors, template assignments, and common building loads, plus `idempotencyKey`.
  - `src/lib/agent/validate-spec.ts`: `validateProjectSpec(spec)` dry-run engine that checks for missing or unconfirmed electrical ratings (`isConfirmedByUser === false` or omitted kW/V/lengths) and returns `readyToCreate`, `missingOrAssumedFields` with IEC/NEMA defaults from `src/lib/country-defaults.ts` and `src/lib/project-defaults.ts`, and `estimatedTotalsPreview`.
  - `src/lib/agent/build-project.ts`:
    - `createProjectFromSpec(user, spec)`:
      - Checks 60s idempotency cache/audit log for `idempotencyKey`.
      - Runs inside `db.$transaction(async (tx) => { ... }, { timeout: 15000 })`.
      - Checks and decrements `user.credits` (unless `ADMIN`), throwing 402 if `< 1`.
      - Pre-generates UUIDs (`crypto.randomUUID()`), converts any room `explicitLoadKva` by multiplying by `powerFactor` into Watts (`ApartmentRoom.connectedLoad`) and back-calculates `loadDensity = Math.max(0, (targetWatts - acWatts) / area)` so later UI edits preserve the custom load.
      - Pre-computes complex-wide residential diversity factor, `FloorItem` loads/currents, and `BuildingLoad` `cableSize` (`sizeCableAndBreaker()`), batch-inserts via `createMany()`, and stamps `engineVersion: ENGINE_VERSION`.
    - `updateProjectLoads(user, spec)`: Applies targeted load/template/building mutations and runs `recalculateProjectBuildings(projectId)`.
    - `getProjectComplianceSummary(projectId)`: Computes total connected kW, max demand kW/kVA, main incomer breaker (`safeIncomerIr`), transformer/generator kVA, phase balance unbalance %, and any IEC/NEMA compliance warnings.
    - `getProjectBOM(projectId)`: Aggregates switchgear by category/rating (ACB, MCCB, MCB, RCCB) and cable schedules by size/material for instant procurement takeoffs.
- **How we prove it works:**
  - Comprehensive unit & integration tests in `src/lib/agent/__tests__/validate-spec.test.ts` and `src/lib/agent/__tests__/build-project.test.ts` covering missing-field detection, VA-to-W PF conversion, back-calculated `loadDensity`, zero-credit 402 rollback, 60s idempotency dedupe, BOM aggregation, and compliance diagnostics.

### Step 5: Zero-Dependency MCP Server (`/api/mcp` + `scripts/procal-mcp-stdio.ts`)
- **Files:**
  - `src/lib/mcp/server.ts`: JSON-RPC 2.0 MCP protocol handler (`initialize`, `notifications/initialized`, `tools/list`, `tools/call`, `prompts/list`, `prompts/get`) exposing the `drawing-to-procal-workflow` prompt and all 8 tools:
    1. `get_engineering_catalog`
    2. `validate_project_spec`
    3. `create_project_from_spec`
    4. `update_project_loads`
    5. `check_project_compliance` (fast code compliance & violation audit)
    6. `get_project_bom` (aggregated switchgear & cable takeoff schedule)
    7. `get_project_sld` (calls `generateSLD()` + `generateSLDPages()` + `schematex.render(dsl, { mode: "preview" })` + `schematex.parse(dsl)`)
    8. `get_project_report` (returns compliance summary, targeted `/calculator?projectId=...&floor=...` deep links, and 1-hour signed `/api/projects/[id]/pdf?token=...` download link; only runs eager `generateServerPdf()` if `includeBase64: true`)
  - `src/app/api/mcp/route.ts`: Next.js App Router `POST` and `GET` handler authenticating via `getSessionUser()` (`Bearer procal_sk_...` or cookie) and dispatching to `handleMcpRequest()`.
  - `scripts/procal-mcp-stdio.ts`: Thin, zero-DB-dependency `stdio` bridge that reads `PROCAL_API_KEY` and `PROCAL_URL` from env, forwards JSON-RPC messages from `stdin` to `POST /api/mcp`, and writes local `.pdf` / `.svg` files when `outputFilePath` is requested.
- **How we prove it works:**
  - End-to-end MCP tool suite test in `src/lib/mcp/__tests__/server.test.ts` exercising `initialize`, `prompts/get`, and all 8 tools in sequence (`get_engineering_catalog` -> `validate_project_spec` -> `create_project_from_spec` -> `update_project_loads` -> `check_project_compliance` -> `get_project_bom` -> `get_project_sld` -> `get_project_report`), plus `npx tsc --noEmit` and `npm test`.

## NOT in Scope (Explicitly Deferred)
1. **Server-Side Vision LLM Drawing Extraction (`POST /api/projects/import-drawing`):** Deferred because external MCP clients (Claude Desktop, Cursor) already provide native multimodal vision at zero LLM token cost to ProCal.
2. **Publishing a Separate npm Package (`@procal/mcp-server`) to npmjs.org:** Deferred; engineers can connect directly via Streamable HTTP (`/api/mcp`) or run `npx tsx scripts/procal-mcp-stdio.ts` from the repo without external registry publishing overhead.

## Failure Modes Matrix

| Codepath | Realistic Production Failure | Test Covers It? | Error Handling Exists? | User-Visible Outcome |
|----------|------------------------------|-----------------|------------------------|----------------------|
| `src/proxy.ts` & `getSessionUser()` | Agent sends revoked/invalid `procal_sk_...` or omits header on `/api/mcp` | YES (`auth-api-key.test.ts`, `proxy.test.ts`) | YES | Returns `401 Unauthorized` JSON-RPC error (never 307 HTML `/login`) |
| `validate_project_spec` | Architectural drawing omits appliance wattages or system voltage | YES (`validate-spec.test.ts`) | YES | Returns `readyToCreate: false` + structured confirmation table with IEC/NEMA defaults |
| `createProjectFromSpec()` | Non-ADMIN user has `0` credits remaining | YES (`build-project.test.ts`) | YES | Returns `402 No credits remaining`; 0 DB rows written |
| `createProjectFromSpec()` | Agent times out and retries identical request within 60s | YES (`build-project.test.ts`) | YES | Idempotency check returns existing project; only 1 credit deducted |
| `createProjectFromSpec()` | Invalid foreign key or DB failure midway through 300-apt insert | YES (`build-project.test.ts`) | YES | Interactive `$transaction` rolls back all rows and credit deduction |
| `get_project_report` | PDF report is 500 KB and would overflow LLM context window if returned as raw Base64 | YES (`server.test.ts`) | YES | Returns lightweight Markdown summary + 1h signed `/api/projects/[id]/pdf?token=...` URL |
